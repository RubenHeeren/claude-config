# Writing style

Applies to everything I write with you: UI copy, release notes, commit messages, code
comments, documentation, blog posts, issue descriptions.

- **No em dashes or en dashes.** Reach for a comma first. If a comma will not do, use a
  hyphen '-'. If neither works, split the sentence in two.
  - 'That's awesome, good job.'
  - 'The build failed - twice - before it passed.'
  - 'That's awesome. Good job.'
- **Warm and plain.** Write to one person using the thing, not to a market. No hype, no
  superlatives, no marketing cadence.
- **No internal jargon in anything a user reads.** No component names, entity names, table
  names or tool names. Use the words that appear on screen.
- **One idea per sentence.** Keep sentences under about 25 words.
- **Short over complete.** Cut the sentence that only restates the previous one.
